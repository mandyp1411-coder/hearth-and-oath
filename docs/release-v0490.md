## Composed safeguards

The existing save coordinator, validated snapshot cache, mandatory reads of both durable keys, conflict/revision/deletion checks and durable rollback remain authoritative. Health comparison metadata is invalidated before an app write enters the async queue, and again on a store write; unload always rechecks supplied live content. File export uses the active live session rather than an older slot copy and never marks browser saving successful. An unchanged but unavailable store says “Browser saves unavailable” while retaining its last known durable timestamp and without inventing unsaved choices.

New guide metadata is optional and strict. Old saves do not acquire it during migration or automatically open guidance. Actual fresh starts and public successors get their own marker; dismissal travels with that life. Explicit Help reopening is presentation-only. Current pending events, encounters, replies, commitments and journeys take priority; native activation rederives a valid current suggestion before invoking an existing handler. Provider previews remain read-only and bounded. The extracted shared meeting selector retains v0.48's exact `objectiveServiceId` ownership rule as well as family archive/shrine offers, so guidance does not hide current story controls or grant them to another provider.

Save labels and timestamps stay quiet. Failure copy uses the existing always-mounted polite atomic status span, and async completion updates mounted copy/visibility without replacing focused controls. Native Enter/Space, modal Escape/trap/focus return and detached-control rejection retain their existing contracts. Source/semantic evidence is not a screen-reader speech or browser-layout test.
