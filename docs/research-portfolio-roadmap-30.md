# Research portfolio: Roadmap 30

## Leaf checkpoint

The isolated leaf starts at published v0.48.0 source `b24cba83`. Its first
checkpoint adds only the immutable two-question definitions, research-owner
schema/validation/projections, and fast pure-state tests. It does not wire the
engine, service adapters, conversations, UI, inheritance, build or publication.

The questions are **The Third Mark on the Axle** and **The Bell That Rang Before
the Storm**. Their source fragments extend the existing millwright, craft,
watchers, signals and stars lore without converting a copied excerpt into a
visit to its distant original. Maker marks, repair shares, maintenance approval,
an observed signal, an alarm heard and an explanation of that alarm remain
different claims. Unsupported interpretations are revisable drafts, not failed
quests. Supported uncertain conclusions are complete outcomes.

## Authority and bounded state

`research-definitions.js` is a frozen closed catalog. Reading it does not create
state, accept work, discover lore or award anything. The optional
`researchPortfolio` envelope is intended to be created on the first real
invitation choice or acceptance, not by initialization or migration.

There are at most two current-life runs and one active run. Exact current-life
owner IDs are mandatory. A terminal question cannot be reopened or gain later
evidence/consent. Each public copy records its original institution separately
from its actual local custody, requesting, preparation and receipt dates. No
arrival token or inferred map visit is used. Evidence kinds reuse the shared
`objective-evidence.js`; owner validation checks the precise meaning of every
token against actual attended steps, copy provenance and actor custody revision.

Each required public copy takes one attended day. The home comparison takes one
attended day and has one practice receipt. Runtime must apply Scholarship +1
exactly when this first comparison completes, respecting its normal skill cap;
state constructors and validators do not award anything. Research has zero Gold
income, no commission credit and no faction-rank effect. Living costs remain
ordinary engine accrual. Depositing directly at the real archive may take zero
days; a home collection takes one attended day. A self-only folio grants no NPC
knowledge.

All live service actors require an exact trusted NPC16 record with the correct
slot, ID, name, role, location, observation and capture dates. A public archivist
handoff is an explicit dated custody revision. It changes later public copying,
not earlier source attribution, private testimony or personal consent. A
craftsperson's present practice is never called an eyewitness account of the
old mill. Hearing their private admission and permission to quote it are separate
owner/person/source-scoped evidence. Public historical records need no such
personal permission.

Conclusions save exact propositions, cited sources, open questions and credits.
Public/private/self publication previews exclude unacquired sources and private
quotations without an applicable grant. An actual archive/home-collection receipt
is necessary before an exact recipient can become eligible for a later recall.
The future conversation adapter must still establish actual presence and a
completed reply; the pure candidate function is not a conversation writer.

## Next checkpoint requirements

The following are not implemented or tested by this leaf checkpoint:

- Narrow actual local-public-copy lending actions, accepted project progression,
  household residence checks, and provider availability after attended time.
- Engine action/choice dispatch, mutual exclusion, needs/calendar interruptions,
  one-time practice application, and close-life handling.
- Exact event snapshots, owner-validated literal narrative preservation and
  recipient-specific completed-conversation receipts.
- Home/Archive/Journal views and public-only inherited folio display. Private
  permissions must not be carried into a successor's usable authority. Do not
  simply transfer the current-life envelope to an heir.
- NPC16 reference retention for research cast/custody and pending-person pinning.
  Without those reference hooks the existing roster can prune a historical
  participant whose identity this owner correctly requires.

Calendar dates alone do not order an action against its following roster
reconciliation. A source, consent or reply completed while its exact actor was
available may share the retirement day subsequently written by `afterAction`.
Historical validation permits equality at that day boundary, but never a later
day. New work must use `researchActorAvailable` against the actual current
service roster and exact unretired NPC record, even on the same day. Public
custody revisions separately distinguish earlier and later holders when a
handoff happens on that shared date. This prevents an otherwise valid completed
save from becoming invalid merely because reconciliation ran after the proof.

The existing service edition blocks ordinary remote conversations. Do not loosen
that gate to implement lending. This route should expose only the finite local
public catalog; no private testimony appears through it. Optional private
consultation still requires the exact person at their real work room. A
same-role replacement does not inherit a private admission or an informed
recipient's memory.

records; they are not engine-played saves or browser runs. They cover catalog

exact-recipient recall eligibility, terminal state, one active case, and bounded
pending/unfinished project state.

No full engine test, semantic runtime test, aggregate release gate, offline
build, browser, main-tree edit or publication is included in this checkpoint.

## Coordinated engine verification, 2026-10-17

The final serial public-engine run is **11/11 PASS**, zero failures or skips,
14.86 seconds. It used `UV_THREADPOOL_SIZE=1`, a 512 MB V8 heap, test concurrency
one and a 90-second process limit. The execution lane was released to the parent
when the process reached its terminal result.

Coverage includes both complete home-only questions from genuine existing
lodgings; a non-Scholar with an unformed calling; a Scholar chosen through the
actual career action whose paid career ledger stays separate; recoverable wrong
interpretation; a private deposit with an actual later exact-recipient

real-workbench-only private testimony and scoped quotation requests; an actual
calendar deadline interruption with zero attendance and remaining-day resume;
cancelled optional consultation; malformed import rejection; and the focused
life-closure adapter. Whole-save round trips cover the critical pending,
accepted, completed, interrupted and conversation states exercised by these
scenarios. These are controlled clones of one genuine played save, not newly
played lifetimes. The direct context cancellation test and focused life-closure
test are explicitly adapter tests; neither claims a played age-22 retirement.

The first engine run was **10/11 PASS**. Its early private-access assertion
incorrectly demanded that the ordinary archivist talk action be absent at home.
Existing v48 service projection can list it without a room ID, while the
unchanged service-access layer correctly disables it. The assertion now checks
that no enabled remote talk or actual spoken message is possible. Source review

settlement, not a missing derived `roomId`. The final run includes a stale
pending-reply displacement regression. Pure negative checks additionally cover
another settlement's archive, moved recipient, retired original, same-role
successor, stale name and recorded death. Existing generic service gates were
not changed.
